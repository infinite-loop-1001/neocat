# 08｜TDD 任务对与执行门禁

## 1. 规则

| 序号 | 任务类型 | 内容要求 |
|---|---|---|
| 奇数（1, 3, 5 …） | **只写会失败的测试** | Spock 规格；为编译而必须存在的接口、类型、空壳；**禁止任何业务实现**。提交时该规格必须为红 |
| 偶数（2, 4, 6 …） | **只写实现** | 让上一张奇数规格转绿。不扩大范围、不新增规格；漏测回到下一对奇数补 |

**门禁**：`mvn -f <module>/pom.xml test` 必须全绿才能进入下一对。偶数任务结束时若红，不得前进。此表为原任务历史；运行参数实现已由按用途拆分的静态配置替代，见 12 文档。

**允许的例外**：`infra` 包中的 MyBatis Mapper、ClickHouse DAO、Apollo/站内通道适配器可以**写实现但不写测试**（外部依赖由用户人工补齐 endpoint 后手动验证），但**必须**能被 `@Tag("integration")` 排除在默认测试之外。

**汇报粒度**：每完成一个**模块组**（下表 `G*`）停下汇报。
