# Metric count 与 Heartbeat 真实数据链路

## 已确认范围

后端、Protobuf、Java SDK、ClickHouse 增量迁移、测试和契约文档同步实现；不运行数据库迁移，
不自动启用 SDK 后台采集。前端保留既定接口及布局。

## Metric

独立查询模块提供 metrics / labels / count。count 使用数值观测次数 valueCount，不使用
通用调用 count，不累计排名列表。过滤同键 OR、异键 AND，空条件为全量。不同标签组合
读出与重分桶时保留完整身份。全量包含 other 且每个观测计一次。

持久化小时标签归属与原始标签 JSON，避免解析有歧义的 key=value; 串。当前小时归属和
历史元数据共同判断匹配组合是否被合入 other；不确定则 null/MERGED_OTHER。不证明
采集完整的空桶返回 NO_DATA，未来桶 NO_DATA，丢弃优先于合并缺口。

排名必须与实际写桶身份一致：本轮保留采集期已分配的独立组合，不在固化时仅更改元数据
造成桶身份失配。独立组合内按上报次数展示排名；严格重新选举 TopN 并迁移所有已落库数值
分布不是本轮 count API 的前提，现有实现的先到先得限制必须在文档公开。

## Heartbeat

原 5 个字段保留编号，增加字段 presence，新指标缺失为 null。旧字段的旧客户端零值保持
兼容，新客户端显式声明可用指标区分未上报和合法零；JVM -1 未定义值不入库。
后端固定支持前端的 20 项指标。SDK 保留手动入口，新增显式 JVM 采样入口；仅可靠识别的
内存池和 GC 分项上报，不将 old 等同 full，不可靠值不猜测。

每实例每桶取最后有效采样：保存 value_last 与 value_last_time，按事件时间选最后值，
不使用 sum/max/avg。分钟、小时、日聚合与历史查询均传递最后值及其事件时间。
旧历史桶缺少最后值时保持缺口。GC 为启动以来累计值，保留重启归零。

## 存储及验证

增量迁移补 value_count、最后值、covered_seconds 兼容列及 Metric 标签归属表。标签元数据
快照重复写用版本去重，不把快照 sum 成重复次数；现有桶落库增加批次去重键避免相同快照
重复刷写。保留查询时区与自然桶边界。

落地方式：桶写入 source/version，读取先按来源、完整 SeriesKey、原桶取最新快照；
日/周/月整层重建使用全局快照，已存在全局版本时不叠加遗留增量行。Metric 专用
`metricSourceRows` 保留原小时/日时间，不复用把来源提前折叠到目标日的通用返回值。
含分隔符标签使用 versioned Base64URL 身份，普通旧身份保留。允许迟到小时按配置保留
和补刷，关闭窗口再释放；时区 Date 写入/读出均使用平台当地日期。

测试覆盖旧/新协议、缺失与零、SDK、指纹、分析器、最后值乱序/重启/粗桶、HTTP 条件校验、
Metric 全量与 AND/OR、other、跨当前/历史、JDBC 参数化与迁移契约。执行 Maven 后端/SDK
测试、协议检查及前端回归；无真实 ClickHouse 时明确集成验证未完成。
