# 独立类型按职责归包

用户已确认采用「用途分包、相关类型成组」方案。本轮仅整理上一轮拆出类型及必要关联类型，不做额外全仓架构重构，不操作 Git 暂存、提交或推送。

- HTTP DTO 在业务模块 `api/http/dto` 下按用途分组：认证、用户、组织、成员、删除预览、告警规则、告警预览、卡片、序列、报表、Metric、Heartbeat、Problem 等。单一用途的 Trace DTO 保持整组，固定成功响应放在模块内 `dto/common`，不跨业务模块共用。
- 数据库行模型放入原基础设施包的 `row` 子包，Mapper 和仓储仍留在原包。
- 领域返回模型放入所属领域的 `result` 子包，直接配套的结果与枚举一起归组；Metric 标签元数据使用 `metric/metadata`。内部接口结果使用 `api/internal/result`。
- 已有领域事件、公式 AST 与时间范围类型族沿用当前职责包，不将一个类型族分散到多个包；单个实现／SDK 句柄不为增加层级而机械迁移。
- 不改变类名、字段、构造器、行为、JSON、Protobuf、OpenAPI schema 名、SQL 或模块依赖。跨包迁移所需 import、MapStruct、Groovy、MyBatis XML、反射字符串、扫描规则及具名接口导出注解同步调整。
- 既有私有辅助类、局部类型、Builder、生成代码、匿名类型与测试夹具除外。必要关联类型一起迁移，不扩大职责。

验证：先增加归包与旧路径无残留的回归，再执行 IDEA 编译／lint、离线契约与映射定向测试、后端／SDK 全量测试、规范与跨端检查。全量失败与已有 10 项身份基线比较，不将既有失败称为全绿。
