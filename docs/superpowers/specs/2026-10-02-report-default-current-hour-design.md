# 报表默认时间窗口改为当前整点小时

用户已确认：进入报表页时默认窗口是**当前自然小时**（整点对齐，如 `20:00 – 21:00`），
不再是 `18:59 – 19:59` 这种从当前时刻往回滚、带零头的「最近 1 小时」。

## 为什么

滚动窗口的区间带零头，既不好读，也无法与整点的历史窗口直接比较；
`TimeScope` 是全部报表共用的，因此这一个改动会同时影响
Transaction / Event / Problem / Heartbeat / Metric / Dependency。

## 定义只有一份

新增 `front/src/api/time-range.ts`：自然边界对齐（整点 / 周一 / 月初）、
`range` 写法、以及 `currentHourScope()`。`TimeScope` 与各报表页的初始 `range`
都从这里取。

必须同源的原因：两边各算一次的话，控件显示 `19:00 – 20:00`、页面却按别的范围取数，
不会报任何错，只会让人看到对不上的数字。

## 不下发新的 range 取值

「当前小时」在 UI 上是一个选项，但发出的仍是契约里已有的 `HOUR:<epoch millis>`，
因此**不需要改后端契约**。`HOUR:` 本来就是窗口导航的载体，这里只是让默认值也用它。

## 连带修正（默认窗口暴露出来的）

改成当前整点小时后，窗口右端落在 `now` 之后，以下几个原先被滚动窗口掩盖的问题失效了：

1. **未来桶没有被编造数值的义务**。`seriesInRange` 与 `heartbeatPoints` 原会对
   `now` 之后的桶生成 OK 数值。后端对尚未发生的桶没有对应行→NO_DATA。
   给未来编造数据正是「缺数据不等于零」要防的错误，已改为缺口。
2. **当前小时的 QPS 分母**是「整点 → now」的实际秒数（PRD 03 §4），不是整段 3600 秒。
   `namesInWindow` 原来一律用窗口长度。
3. **点 ◀ 必须有反应**。原「从快捷范围切到窗口模式」只做「对齐到当前窗口」，
   而默认窗口本身就是当前窗口，于是第一次点 ◀ 会毫无反应。现在 ◀ 会真正往前一个窗口，
   ▶ 仍只落到当前窗口（不进入未来）。
4. **单一日期/时长的重复实现**收敛到 `time-range`，`TimeScope` 不再自带一份。

## 测试

- 新增：默认即整点窗口、◀ ▶ 行为、下拉「当前小时」与默认项一致、默认范围与各页面初始 `range` 同源。
- 调整：QPS 分母、heartbeat 默认 range 断言。
- 动线新增：默认窗口下未来桶全为缺口且含实时桶（45 个检查点）。
