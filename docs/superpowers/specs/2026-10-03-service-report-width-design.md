# 服务报表全宽布局

日期：2026-10-03
状态：已实施，测试、构建及运行页面检查通过。

## 范围

服务报表不再受通用面板的 1280px 最大宽度限制。Transaction/Event 的 Type、Name、趋势页面及 Heartbeat、Dependency 使用显式 `service-report-panel` 类，将内容面板设置为 `width: 100%; max-width: none; min-width: 0`。Metric、Problem 保留既有全宽布局。

保留工作区左右边距、侧栏、表格字段、图表高度与业务交互。趋势页仍使用自适应主列和固定 240px 筛选栏，窄屏沿用现有布局规则。管理页、登录页、服务列表、大盘及 Trace 不扩改。

## 验证

编译真实模板，检查范围内各页面启用全宽类，范围外页面未启用；锁定通用面板 1280px 限制与趋势筛选栏 240px 宽度。执行前端测试、类型检查、生产构建及动线检查。浏览器检查 Type、Name、趋势、Heartbeat、Dependency 的实际面板宽度和内容渲染。

此为本地前端验收，不代表后端现场联调。目录不是 Git 仓库，无法提交或推送。

## 实施证据

- 生产修改仅涉及五个页面根节点的显式类及全宽选择器，未改业务脚本、表格字段、图表高度和固定筛选栏布局；Metric/Problem 原有规则保留。
- 新增两项回归在修改前失败、修改后通过。全量 97 项前端测试、47 个动线检查点、类型检查和生产构建通过。
- 1440px 桌面浏览器检查：Transaction Type/Name、Event Type、Dependency 面板从 x=256 到 x=1416，仅保留正常工作区边距；Heartbeat 因纵向滚动条，宽度为 1145px，同样填满工作区。趋势页筛选栏实际宽度仍为 240px。
- 当前浏览器提供的 desktop 预设为 1440px，未声称已实测用户截图的 2000px 视口；该宽度下的扩展由移除最大宽度规则及回归保证，仍可由用户在原宽屏验收。
