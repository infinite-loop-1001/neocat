# 04｜Metric 与依赖

## 1. Metric 范围

Metric 是一个服务上报的数值指标：

```text
指标名 + 若干标签键值 + 数值 + 事件时间
```

标签键由上报方自定，平台不预注册。

## 2. 标签组合规范化

同一服务、同一指标名、同一小时内：

1. 将标签键按稳定顺序规范化；
2. 相同键值组合视为同一序列；
3. 按上报次数从高到低排名；
4. 保留最多1000个真实标签组合；
5. 其余组合进入一个 `other` 序列。

因此可见序列最多为1000个真实组合加1个 `other`。Top1000限制本身不拒绝上报；整体系统过载时仍可能按统一规则丢监控数据。

## 3. 小时重排

每个自然小时独立排名：

```text
10:00 小时排名结束
→ 11:00 重新从空排名开始
→ 同一标签组合可能从独立序列变成 other，或反向变化
```

跨小时查看具体标签组合时：

- 该小时独立保留：显示实际值；
- 该小时被并入 other：显示缺口，并标记“该小时已合入 other”；
- 不用 other 值冒充具体组合；
- 不把缺口显示为0。

`other` 是可独立查看、画趋势、计算分位和环比的序列，但每小时包含的实际组合可能不同。

## 4. Metric 统计

对每个序列支持：

- 上报次数；
- 数值总和；
- 平均值；
- 最小值/最大值；
- tp50、tp90、tp95、tp99、tp999、tp9999；
- 时间桶趋势；
- 日/周/月环比；
- 组织大盘钉选。

同一时间桶只有一个值时，各分位与该值相同。

## 5. Metric 大盘行为

### 当前前端的 count 总览与详情

服务的 Metric 入口按指标名称展示并排小图，每图默认仅一条全量 count（上报次数）曲线。
全量包含所有真实标签组合及 `other`，不是数值总和，不是可见 Top 标签组合之和。
点击标题或“查看详情”进入 `/svc/:service/metric/:metric`，默认仍展示总量，不预选标签。

详情只在用户选择标签后展示符合条件的聚合 count，一次只画一条线：同键多值 OR、
不同键 AND；清空条件恢复全量。提供当前指标的可搜索标签候选、所选条件和清空入口。
具体条件匹配的数据若已合入 `other` 且不能还原，桶显示 `null / MERGED_OTHER`，不得
以可见子集冒充完整结果；确认没有匹配上报且数据完整时可显示 `0 / ZERO`。

总览与详情来回保留时间范围，详情 URL 保存标签筛选。默认当前整点小时，历史窗口与
时间控件一致，不能前进到未来窗口。两个页面沿用断线缺口及高对比实线。

指标目录、标签候选及 count 聚合已接入真实后端（2026-10-02），部署前须执行相应
ClickHouse 迁移。旧历史缺少标签归属或观测次数时保持缺口，不伪装精确统计。
§4 的其他统计和下面的大盘行为不属于本轮新增 count 页实现。

### 大盘对象口径

Metric 的一个具体标签组合或 `other` 可以作为一个指标对象被大盘卡片引用。标签集合是对象身份的一部分，不能在卡片保存后静默改变。

如果跨时间范围内标签组合出现缺口，卡片显示缺口；若卡片目标是 `other`，则按 `other` 自身序列计算。

## 6. 依赖对象

依赖来自跨服务调用关系：

- 上游服务；
- 下游服务；
- 调用次数；
- 失败次数/失败率；
- 平均耗时和适用分位；
- 时间桶趋势；
- 代表性 Trace。

依赖不是一次 Trace。依赖是长期服务关系汇总，Trace 是单次请求的调用树。

## 7. 依赖采集与缺失

调用方 MessageTree 已记录远程调用时，即使被调用方 MessageTree 没有到达：

- 依赖边仍计入调用次数；
- 能统计调用方可观测到的失败/耗时信息；
- Trace 组装时将被调用方树标为缺失。

只有在调用方关系本身没有被观测到时，依赖边才不产生。

## 8. 依赖页面

默认布局为上下游列表，不以拓扑图作为一期主入口。

### 下游列表

展示当前服务调用的服务：

- 下游服务名；
- 调用次数；
- 失败率；
- 平均/分位耗时；
- 当前时间范围趋势入口；
- 代表性 Trace 入口。

### 上游列表

展示调用当前服务的服务，字段与下游一致。

点击一条依赖进入该服务对之间的趋势，并可选择代表性 Trace。

## 9. Metric/依赖验收

1. 1000个真实标签组合之外有单独 `other`。
2. 具体组合被并入 other 的小时显示缺口，不显示 other 值。
3. Metric 分位基于桶内原始数值分布，不平均子桶分位。
4. 依赖统计不因下游 MessageTree 缺失而整条丢失。
5. Trace 缺失节点与依赖统计缺失分开表达。
