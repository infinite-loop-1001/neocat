# 00｜产品总纲

## 1. 产品定位与目标

NeoCat 是面向公司内部的应用监控平台，借鉴 CAT 的核心监控工作流，但不兼容原版 CAT 客户端和原版上报协议。

一期解决三件事：

1. **更快发现故障**：服务报表、Problem 和可配置告警；
2. **更快定位根因**：从汇总指标进入某次调用，再查看由多棵 MessageTree 组合出的 Trace；
3. **用数据做性能优化**：耗时分布、分位、环比、机器维度和依赖关系。

一期还提供：

- 服务首次合法上报后自动出现在可查询服务中；
- 组织叶子大盘；
- 大盘卡片的同一指标多统计项聚合与四则运算；
- Metric 标签维度；
- 告警规则保存前预告警和手动启停。

## 2. 产品事实源与范围原则

本目录是当前产品设计的唯一事实源。旧规格和旧实现计划只用于历史追溯。

一期以产品行为为验收边界，不以现有页面是否存在为边界。原型中曾出现但本设计没有纳入的全局大盘、应用总览、Business 漏斗、P1/P2、告警确认、问题单、CPU/Load 等能力不属于一期。

## 3. 角色模型

### 3.1 系统角色

| 角色 | 核心权限 |
|---|---|
| 普通用户 `USER` | 查看当前可查询服务和报表；为任意服务配置服务告警 |
| 管理员 `ADMIN` | 创建普通账号、重置密码、管理组织树和成员、配置平台慢阈值和通知通道 |
| 超级管理员 `SUPER_ADMIN` | 管理员全部能力；授予或取消 `ADMIN`；平台初始化的第一个管理主体 |

管理员权限和组织业务权限分离。管理员、超管不会因为系统角色自动获得组织大盘或组织告警访问权。

### 3.2 业务使用角色

值班人员、开发人员、组织成员不是独立的系统角色，而是同一个账号在不同业务场景下的使用方式：

- 值班：告警规则触发通知后，进入服务报表和 Trace；
- 开发：从 Transaction/Event/Problem 找慢点或失败点并优化；
- 组织成员：查看和修改自己有权限的叶子大盘和组织告警；
- 管理员：管理账号、组织和平台配置。

## 4. 共享业务对象

### 4.1 服务与实例

- **服务**：以上报的 `serviceName` 为唯一标识。同名即同一服务；平台不提供手工建服务。
- **实例**：服务下以上报的 `instanceId` 唯一。通常是 IP，但产品不强制具体格式。
- 服务不绑定组织；登录用户可以看到当前筛选范围内有数据的任意服务。
- 服务列表和实例列表按当前报表类型、当前时间范围动态过滤；没有该类型数据的服务/实例不展示。

### 4.2 MessageTree 与 Trace

```text
MessageTree = 一个服务进程内、一次请求上下文中的本地调用树
Trace        = 多个跨服务 MessageTree 组合出的完整调用链
```

树级 ID：

| ID | 语义 |
|---|---|
| `messageId` | MessageTree 全局唯一 ID，也是树级幂等键 |
| `rootMessageId` | 跨服务 Trace 的根 MessageTree ID |
| `parentMessageId` | 当前 MessageTree 的上游 MessageTree ID |
| `nodeId` | MessageTree 内 Transaction/Event/Heartbeat/Metric 节点的唯一 ID |

Trace 组装只负责建立跨服务调用关系；一棵本地树仍独立参与本服务的统计。

### 4.3 指标对象与统计项

所有报表、大盘和告警都引用统一的“目标时间序列”概念：

```text
目标序列 = 服务 + 报表类型 + 指标对象 + 统计项 + 维度范围
```

示例：

- `order / Transaction / URL / POST /orders / Hits / all-machines`；
- `order / Transaction / URL / POST /orders / tp99 / instance-10.0.0.8`；
- `order / Event / business / order-created / QPS / all-machines`；
- `order / Metric / order.amount{city=上海,channel=app} / p95`；
- `order / Heartbeat / heap-used / instance-10.0.0.8`；
- `order / Problem / slow-sql / select_order / Hits`。

一个大盘卡片只允许针对**一个服务的一个指标对象**引用多个统计项；大盘可以有多张卡片，因此可以覆盖不同服务和指标对象。

### 4.4 时间桶与时间范围

每个趋势点表示左闭右开区间：

```text
[bucketStart, bucketEnd)
```

横轴显示 `bucketStart`，Tooltip 显示完整区间、覆盖状态和数据质量。

平台时区在首次初始化时设置，一期运行中不可修改。所有自然周期、环比、告警分钟点均使用该固定时区。

固定周期和快捷范围见 [03-reports-time-buckets.md](./03-reports-time-buckets.md)。

## 5. CAT 口径的 QPS

CAT Transaction 报表内部字段称为 `tps`，页面通常显示为 `QPS`。NeoCat 沿用这个产品显示名，但明确其语义为所选范围内的平均处理速率：

```text
QPS = 范围内总次数 / 报表实际覆盖秒数
```

规则：

- 当前未结束小时：分母是平台时区当前小时起点到当前时刻的实际秒数；
- 完整历史小时：分母为 3600 秒；
- 日、周、月或自定义范围：分母为该报表实际覆盖的秒数；
- 多机器先合并总次数，再除以公共分母；不能平均机器 QPS；
- 趋势默认显示桶内 Hits 总次数，不把 count/min 直接标成 QPS；切换到 QPS 时才按桶实际覆盖秒数换算。

参考依据：

- [CAT DeepWiki](https://deepwiki.com/dianping/cat/4.1-analyzers-and-consumers)；
- CAT `TransactionAnalyzer.queryReport`、`TransactionStatisticsComputer`、`TransactionReportService`、`TransactionReportHourlyGraphCreator` 源码。

## 6. 统一数据质量语义

| 状态 | 业务含义 | 展示 |
|---|---|---|
| 有数据 | 当前范围内存在可用观测 | 正常数值 |
| 确认无调用 | 数据完整且次数为零 | 次数类显示 `0`；耗时/比例类显示无值 |
| 缺数据 | 采集丢弃、分析失败、尚未完成或序列不存在 | `null`/缺口，并标明原因 |
| 部分覆盖 | 滚动范围首尾桶只覆盖部分时间 | 数值照实际覆盖计算，Tooltip 标记 |
| 实时桶 | 当前仍在写入的桶 | 原位刷新并标记实时/未完成 |
| Trace 过期 | 汇总仍存在，但原始树超过 7 天 | 禁用下钻并提示已过期 |

缺数据不等于零。告警的缺数点是未知，不参与比较并打断滑动窗口。

## 8. 完整业务流程链路矩阵（32条）

| 编号 | 链路 | 触发 | 主要步骤 | 结果/异常 |
|---:|---|---|---|---|
| 1 | 平台初始化 | 首次部署 | 初始化时区、超管、默认阈值 | 平台可登录 |
| 2 | 创建账号 | 管理员操作 | 创建 USER、生成临时密码 | 首次登录必须改密 |
| 3 | 登录 | 用户提交凭据 | 校验账号、创建滑动会话 | 进入最近服务 Transaction 或服务列表 |
| 4 | 重置密码 | 管理员操作 | 设置临时密码 | 下次登录强制改密 |
| 5 | 授予管理员 | 超管操作 | USER ↔ ADMIN | 仅超管可执行 |
| 6 | 禁用/启用账号 | 管理员操作 | 失效会话、移除收件人、保留组织关系 | 启用后恢复组织成员但不恢复收件人 |
| 7 | 建组织树 | 管理员操作 | 建节点、校验父节点和环 | 叶子可挂大盘 |
| 8 | 管理成员 | 管理员操作 | 加入/移除任意节点 | 即时重算叶子权限 |
| 9 | 变更组织拓扑 | 管理员操作 | 叶子转非叶子前检查资源 | 有大盘/规则时阻止新增子节点 |
| 10 | 删除叶子 | 管理员操作 | 影响预览、二次确认、原子级联 | 大盘/卡片/组织规则删除 |
| 11 | 本地上报 | 服务产生请求 | 形成 MessageTree 并发送 | 进入接收链路 |
| 12 | 上报校验 | 平台收到树 | 校验协议、ID、时间、字段 | 非法/过期整棵拒绝 |
| 13 | 自动发现 | 首次合法身份 | 创建服务/实例目录 | 即使后续队列满也可发现 |
| 14 | 上报幂等 | 重试上报 | 检查全局 messageId | 相同内容幂等；冲突拒绝 |
| 15 | 过载丢弃 | 队列满 | 丢弃监控数据并快速返回 | 业务不阻塞，不补算 |
| 16 | 实时分析 | Consumer 取树 | 扇出各 Analyzer 和 Trace Store | 单域失败不阻断其他域 |
| 17 | Transaction 诊断 | 用户选服务 | Type → Name → Hits 趋势 → 机器 → 取样 | 进入 Trace |
| 18 | Event 诊断 | 用户选服务 | Type → Name → Hits/QPS 趋势 → 取样 | 无耗时分位 |
| 19 | Problem 诊断 | 失败/慢规则派生 | 分类 → 异常名/Name → 趋势/取样 | 慢类有分位，异常无分位 |
| 20 | Heartbeat | JVM 上报 | 实例列表 → Top N 折线 → 机器明细 | 不合并 JVM 值 |
| 21 | Metric 诊断 | Metric 上报 | 小时内排名 → Top1000 + other → 趋势 | 被合入 other 的具体序列显示缺口 |
| 22 | 依赖诊断 | 跨服务关系上报 | 上下游列表 → 趋势 → Trace | 缺下游树显示缺失节点 |
| 23 | 时间滚动 | 分钟/小时边界 | 实时桶 → 小时 → 日/周/月 | 按留存期限清理 |
| 24 | 创建大盘 | 叶子成员操作 | 选服务指标对象 → 统计项/公式 → 卡片 | 卡片默认全机器聚合 |
| 25 | 编辑卡片 | 叶子成员操作 | 修改公式/时间/阈值线 | 关联规则跟随公式，窗口清零 |
| 26 | 创建服务告警 | 登录用户操作 | 目标 → 条件 → AND/OR → X点 → 收件人/通道 | 保存后关闭 |
| 27 | 创建组织告警 | 叶子成员操作 | 从大盘指标并集选目标 → 配规则 | 只能选有效成员收件人 |
| 28 | 预告警 | 保存前表单变化 | 读取最近完整分钟点试算 | 只展示，不发送、不留历史 |
| 29 | 启用告警 | 用户手动操作 | 只从启用后完整点建立窗口 | 满足窗口直接通知 |
| 30 | 运行告警 | 每个完整分钟点 | 回看 X 点滑动窗口 | 满足则每分钟发送，不留触发历史 |
| 31 | 规则变更 | 编辑/卡片变化 | 关闭规则或清零窗口 | 需重新手动启用 |
| 32 | 收件人变化 | 账号/组织变化 | 自动移除无效人 | 无人时仍评估但不发送 |

## 9. 典型端到端用户旅程

### 9.1 值班

```text
规则启用并命中
→ 通知到达
→ 登录 NeoCat
→ 进入对应服务 Transaction/Problem
→ 按 Type/Name 查看 Hits、失败率、QPS、耗时
→ 选择最近30条取样
→ 打开 Trace
→ 查看缺失节点、跨服务耗时和下游关系
```

### 9.2 开发优化

```text
选择服务
→ Transaction
→ Type=SQL/RPC/URL
→ Name
→ 查看 Hits、最小/最大/平均、分位和趋势
→ 切换机器维度
→ 定位异常实例
→ 打开 Trace
→ 优化后比较日/周/月环比
```

### 9.3 组织成员

```text
登录
→ 进入有成员资格的叶子组织
→ 创建大盘
→ 配置同一指标的聚合卡片和阈值线
→ 预览组织告警
→ 保存关闭
→ 手动启用
→ 后续按分钟接收通知
```

### 9.4 管理员

```text
初始化/登录
→ 创建账号
→ 建组织树
→ 加成员
→ 配置慢阈值和通知通道
→ 管理账号启用/禁用
```

## 10. 数据与性能承诺

| 项 | 一期承诺 |
|---|---|
| 体量 | 按几百个服务、每天十亿级调用的中型规模设计 |
| 数据进入 | 正常情况下秒级进入处理链路 |
| 报表刷新 | 分钟级可查询 |
| 告警判定 | 每个完整分钟点判定 |
| 小时汇总 | 至少保留30天 |
| 日/周/月汇总 | 至少保留13个月 |
| 原始 MessageTree | 保留7天 |
| 高压策略 | 允许丢监控数据，不得拖慢业务 |
| 默认完整性 | 默认接近全量；只在高压时降采样/丢弃 |

## 11. 一期总验收矩阵

1. 初始化超管、账号创建、首次改密、登录、登出、禁用/启用。
2. 组织树、成员继承、叶子大盘权限和删除级联。
3. 合法上报自动发现服务/实例；重复 MessageTree 不重复统计。
4. 队列满丢弃且业务不阻塞；单 Analyzer 失败不拖垮其他分析。
5. Transaction/Event 完成 Type → Name → Hits 趋势 → 机器 → 最近30条取样 → Trace。
6. QPS 与 CAT 口径一致；时间桶、部分桶、空数据和实时桶可解释。
7. Problem 五类可查询；异常按异常名、慢类按 Transaction Name 聚合。
8. Heartbeat 只覆盖 JVM，并按实例展示。
9. Metric Top1000 + other、跨小时缺口和分位/环比可用。
10. 依赖上下游列表、趋势和代表性 Trace 可用。
11. 组织大盘卡片支持单指标多统计项聚合、四则运算、维度下钻和缺口。
12. 服务/组织告警支持保存前预告警、手动启停、统一 AND/OR、规则级滑动窗口和通知。
13. 告警触发不产生站内历史；启用、关闭和收件人变更符合规则。
14. 留存、过期 Trace、跨周期汇总和平台固定时区符合设计。

## 12. 相对旧规格的正式修订

| 主题 | V2 修订 |
|---|---|
| Event | 增加 QPS；仍不提供耗时/分位 |
| 趋势默认值 | 默认显示桶内 Hits 总次数，而非默认 count/min |
| 周趋势 | 采用1小时/点，而非 CAT 的1天/点 |
| 快捷范围 | 增加最近3/6/12/24小时、今天、本周；12小时为20分钟/点 |
| 取样 | 每行最近30条、多行展示，替代最多10条 |
| 大盘卡片 | 每张卡片限定一个服务的一个指标对象，可聚合多个统计项 |
| 大盘公式 | 支持同一指标统计项聚合和四则运算；内部校验单位，界面不列单位 |
| 组织告警 | 可引用原始指标或卡片当前计算结果 |
| 告警条件 | 多条件统一AND/OR；连续点数是整条规则的滑动窗口长度 |
| 告警启用 | 保存后默认关闭，必须手动启用；编辑后自动关闭 |
| 告警记录 | 正式触发不保存站内历史，只提供保存前预告警 |
| 时区 | 初始化设定，一期运行中不允许修改 |
| 账号 | 支持禁用/启用，禁用即时失效会话和收件资格 |
| 目录 | 服务/实例按当前报表类型和当前时间范围动态展示 |
| 原型额外功能 | 全局大盘、应用总览、Business、P1/P2、确认、CPU/Load 等不纳入一期 |
