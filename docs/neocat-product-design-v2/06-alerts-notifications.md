# 06｜告警与通知

## 1. 告警模型

一期有两类规则：

- **服务告警**：绑定一个服务的原始指标目标；任意登录用户可以配置和修改；
- **组织告警**：绑定该叶子大盘已引用的原始指标或卡片计算结果；仅叶子有效成员可以配置和修改。

一条规则只绑定一个目标时间序列。规则包含多个比较条件，但所有条件都作用于同一目标。

## 2. 条件模型

每条规则配置：

- 目标序列；
- 一个或多个比较条件；
- 条件连接符：统一 `AND` 或统一 `OR`；
- 整条规则共用的滑动窗口长度 `X`，单位为完整分钟点；
- 接收人；
- 已配置的通知通道；
- 规则名称和描述；
- 启用/关闭状态。

不支持：

- 条件各自不同的连续点数；
- 任意嵌套括号表达式；
- 环比告警；
- 智能异常检测；
- 恢复通知；
- 静默窗口；
- P1/P2 或确认状态。

## 3. 规则生命周期

```text
保存后关闭
→ 手动启用
→ 已启用
→ 手动关闭
→ 已关闭
```

### 3.1 新建

```text
填写目标和条件
→ 保存前实时预告警
→ 保存
→ 规则持久化为关闭
```

保存不会发送通知。

### 3.2 启用

手动启用后：

- 只使用启用时刻之后产生的完整分钟点；
- 不使用启用前的历史点填充窗口；
- 规则窗口从启用后的第一个完整点重新开始；
- 窗口长度为 X 时，至少等待 X 个启用后的完整点才可能首次触发。

### 3.3 编辑

已启用规则编辑后保存：

- 自动变为关闭；
- 原目标、条件或窗口状态不继续沿用；
- 用户需再次手动启用；
- 再次启用时从零建立窗口。

## 4. 保存前预告警

用户填写或修改目标、条件、AND/OR、窗口后，页面可以读取最近完整分钟数据实时试算：

```text
读取最近完整分钟点
→ 按每点条件计算 true/false
→ 按 AND/OR 合并
→ 回看 X 个点
→ 展示当前窗口是否满足
```

预告警结果：

- 只显示“当前会触发/当前不会触发/数据不足”；
- 不发送邮件、钉钉、飞书；
- 不保存告警事件；
- 不改变规则状态；
- 缺数据明确显示数据不足，不把缺数当0。

## 5. 滑动窗口触发

每个新完成的完整分钟点到达时：

```text
当前点 t
→ 取 [t-X+1, t] 共 X 个点
→ 对窗口内每个点计算条件组合结果
→ X 个点全部为 true
→ 在当前点 t 触发
```

例如 X=3：

- 10:02 首次有 `10:00、10:01、10:02` 三个满足点，10:02触发；
- 10:03 回看 `10:01、10:02、10:03`，若仍满足，10:03再次触发；
- 持续满足时，每个新分钟都可能触发和发送；
- 缺数点使包含它的窗口不满足；
- 迟到数据不会回溯已经完成的判定，也不补发过去通知。

多条件规则：

- `AND`：每个点的所有条件都满足，该点才为 true；
- `OR`：每个点至少一个条件满足，该点才为 true；
- X 只属于整条规则，不属于单个条件。

## 6. 缺数与零值

- 完整且确认无调用的次数类点可以是0；
- 没有可用数据的点是未知；
- 未知点不满足“高于”或“低于”任何条件；
- 未知点会打断滑动窗口；
- 不用0模拟采集断流。

## 7. 服务告警

任意已登录用户可以对任意服务：

- 创建规则；
- 修改他人创建的规则；
- 删除规则；
- 启用/关闭规则；
- 选择该服务可用的次数、失败率、QPS、耗时分位、Problem 类型等目标。

服务告警接收人可以是任意启用的平台账号。

## 8. 组织告警

只有叶子有效成员可以配置组织告警。目标选择范围是该叶子所有大盘已引用指标的并集：

- 原始指标仍被任意一张卡片引用：可选且规则继续有效；
- 最后一张引用卡片删除：规则失效但保留；
- 卡片公式修改：规则跟随新公式；
- 卡片公式修改后，规则保存为关闭并清零窗口；
- 规则必须再次手动启用。

组织告警接收人只能从该叶子有效成员中选择，包括祖先组织继承成员。

## 9. 接收人与账号变化

账号被禁用或失去组织成员资格时：

- 自动从相关规则接收人中移除；
- 规则不因此自动关闭；
- 仍有其他接收人时继续评估并发送；
- 没有任何接收人时仍保持启用并继续评估，但不发送；
- 后续补充有效接收人后，从补充时刻重新建立 X 点窗口，不追溯旧异常。

## 10. 通知通道

一期通道：

- 站内预告警仅用于配置页试算，不是正式触发记录；
- 邮件；
- 钉钉；
- 飞书。

管理员未配置好的外部通道不可在规则中选择。已配置通道发送失败只写平台运行日志，不在产品页面提供投递历史。

正式触发流程：

```text
窗口满足
→ 直接向当前有效接收人发送
→ 外部通道失败写运行日志
→ 不保存站内触发事件
```

## 11. 正式告警记录范围

本设计覆盖旧规格中的“站内记录必写、站内有告警列表和历史”规则。NeoCat 一期：

- 不保存正式告警触发事件历史；
- 不提供告警列表和告警历史页；
- 只保存规则本身和启用/关闭状态；
- 保存前提供实时预告警；
- 启用、关闭、编辑等动作不提供产品内操作审计查询。

## 12. 告警验收

1. 新建规则保存后为关闭，不能立即发送。
2. 手动启用后只使用启用后的完整分钟点。
3. X=3时，第3个满足点触发；持续满足时每分钟再次触发。
4. 多条件只支持统一 AND 或统一 OR。
5. 不同条件不能配置不同连续点数。
6. 缺数不当0，并会打断窗口。
7. 编辑已启用规则保存后自动关闭。
8. 组织告警只能引用大盘指标并集。
9. 无收件人时规则继续评估但不发送；补人后重新建立窗口。
10. 正式触发不生成站内历史，发送失败只写运行日志。
