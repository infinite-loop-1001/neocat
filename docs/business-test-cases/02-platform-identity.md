# 第二层：平台、身份与会话（P1）

依据产品01 §2–4、总纲权限矩阵。共用数据见 [DS-ROLE](00-test-data.md#2-ds-role账号与组织)。每例使用独立账号副本或恢复基线；密码不写进测试记录。操作本身同时是NeoCat自身URL/Event数据源，安全约束见 [自身打点要求](09-self-observation.md)；业务无副作用不代表禁止生成正常监控记录。全部待执行。

## I01 初始化输入、重复初始化与时区固定

**目的/追溯**：链路1；验证开通唯一性和时区约束。
**前置与数据**：未初始化隔离环境；Asia/Shanghai；新超管；7位/8位口令、空账号和两次口令不一致各一组；可安全控制初始化状态查询失败的隔离条件。
**步骤**：
1. 打开首页与登录入口，均应自动进入“首次开通 NeoCat”。分别提交空必填项、7位口令、不一致确认口令，逐组观察提示；查看时区选项，至少有 Asia/Shanghai 和 UTC，不允许选择任意非法时区。
2. 在另一窗口也打开开通页。原窗口填写合法账号、8位口令及时区并确认开通，核对转登录但不自动登录。
3. 再次进入开通入口，确认回登录而非显示可提交表单；在仍保留旧开通表单的另一窗口尝试开通，核对提示平台已初始化、本次未创建新账号。
4. 登录后进入平台配置查看时区，并尝试更改。
5. 在独立状态查询故障场景打开首页，查看错误及“重试”；未恢复时重试仍不能进入登录或开通，恢复后重试应进入与真实初始化状态相符的页面。
**功能预期**：非法输入明确拒绝；合法边界可开通并引导登录/首次改密；重复开通不允许；运行期时区只读。状态查询失败明确报错，不默认认为已初始化或未初始化，不出现重定向循环；不确定的提交结果不得自动重发开通。
**数据预期**：拒绝阶段无账号/平台状态残留；成功后仅一份档案与初始超管、默认阈值及三空通道；重复提交不增加账号、不改变时区或首次开通时刻。状态检查和重试只读，不创建平台或超管；提交结果不确定时再次操作先核对服务端状态。

## I02 创建普通账号与首次改密

**目的/追溯**：链路2；正常建号。
**前置与数据**：it.admin；新账号it.new-user、8位临时口令、不同新口令。
**步骤**：
1. 管理员点击“账号管理”，填写账号与临时口令并创建。
2. 新用户独立登录，按提示填写当前与新口令并提交。
3. 进入服务列表，退出后再用新口令登录。
**功能预期**：只能创建USER；首次强制改密，之后正常使用，不再重复要求。
**数据预期**：仅一条字符串账号；首次改密标记由是变否；角色和账号标识不变，密码仅保存散列，旧临时口令失效。

## I03 重复账号、短口令与账号标识不变

**目的/追溯**：链路2；唯一性和口令边界。
**前置与数据**：已有it.dev；新账号it.boundary；空、7位和8位临时口令。
**步骤**：
1. 用管理员创建同名it.dev，记录拒绝结果。
2. 用新账号分别提交空及7位口令，再以8位口令创建。
3. 打开该账号的管理信息，确认无修改账号标识操作；尝试重复保存同一业务创建动作。
**功能预期**：重名与短口令拒绝；8位可创建；不提供改账号名或删除账号功能。
**数据预期**：it.dev原信息不变；it.boundary仅一条；失败不占用一个可登录的半成品账号，也不覆盖已有密码。

## I04 正常登录与最近访问入口

**目的/追溯**：链路3；登录后跳转。
**前置与数据**：已改密用户；三个独立场景：无访问记录、最近访问neocat-backend且当前范围有数据、最近访问同构件隔离自身身份neocat-self-history且当前范围无数据。登录本身会产生neocat-backend数据，不能拿该活跃身份强造无数据前置；缺历史隔离身份则第三组BLOCKED。
**步骤**：
1. 无记录用户登录，观察落点。
2. 另一用户进入neocat-backend报表，退出再登录，观察落点。
3. 对最近访问neocat-self-history且已无当前数据的独立用户退出再登录，确认新登录记录属于neocat-backend，不改变历史身份的数据资格。
**功能预期**：无记录/无可用数据进服务列表；有可用记录进该服务Transaction，不跳其他用户的最近服务。
**数据预期**：访问记录按账号隔离；登录可新增自身登录URL/Event观测，但不能伪造最近访问目标的调用或业务对象。默认数据资格真实匹配，历史身份不当永久空壳展示；不同自身目标不串位。

## I05 无效凭据与未登录访问

**目的/追溯**：链路3；认证隔离。
**前置与数据**：未登录会话；不存在账号、已有账号错密码、已禁用账号三组。
**步骤**：
1. 分别提交三组登录数据。
2. 未登录时直接打开服务报表、Trace、管理页、大盘和告警链接。
3. 正常账号登录后再进入有权限的服务页作为对照。
**功能预期**：失败提示通用，不暴露账号存在性；匿名不能查看受保护内容，跳登录或明确拒绝。
**数据预期**：失败不创建有效会话、不改变账号或业务数据；页面缓存不泄露上一位用户的报表与组织内容。

## I06 首次改密校验与访问限制

**目的/追溯**：链路2、3、4；临时身份不能直接使用业务。
**前置与数据**：待首次改密账号；错误旧口令、相同新口令、7位/8位不同新口令；不一致确认口令。
**步骤**：
1. 临时口令登录，尝试跳转服务报表和管理页面。
2. 在改密页逐组提交错误旧口令、与旧相同、过短、两次输入不一致的新口令。
3. 提交正确旧口令及合法8位不同新口令，再访问正常报表。
**功能预期**：改密前只能改密、查看自身或登出；非法组被阻止，合法组完成后放行。
**数据预期**：失败不改变凭据和强制改密标记；成功仅更新当前账号凭据与标记，不改角色、组织或其他账号。

## I07 多会话与单会话登出

**目的/追溯**：链路3；会话相互独立。
**前置与数据**：it.dev已改密；独立浏览器会话甲、乙。
**步骤**：
1. 甲乙分别登录同一账号并打开报表。
2. 在甲点击“退出登录”。
3. 甲重新访问受保护页，乙刷新并继续查看报表。
**功能预期**：支持同时登录；甲失效需重登，乙保持可用。
**数据预期**：甲的会话失效，乙不被连带注销；账号、成员关系、告警配置不改变。

## I08 30 分钟滑动过期

**目的/追溯**：链路3；区分闲置与有效请求续期。
**前置与数据**：两独立会话甲乙；可准确记录请求时刻，关闭自动刷新与其他隐式有效请求。
**步骤**：
1. 甲登录后保持无有效请求，记录最后有效操作时刻。
2. 乙登录，在最后有效操作后20分钟查看一次报表。
3. 在甲闲置超过30分钟后查看报表；在乙首次登录超过30分钟但距续期请求不足30分钟时查看报表。
4. 乙再闲置超过30分钟后查看报表；过期后重复刷新。
**功能预期**：甲过期，乙步骤3仍可用、步骤4过期；过期刷新不能复活会话。
**数据预期**：乙有效期随有效请求向后延长30分钟；甲不续期。不能只“页面静置”却保留自动刷新并据此判断失败；未能控制隐式请求则BLOCKED。

## I09 重置密码与全部会话失效

**目的/追溯**：链路4；重置即时生效。
**前置与数据**：it.admin；普通用户副本有甲乙两会话；新临时口令及下一次改密口令。
**步骤**：
1. 管理员在账号管理对目标点击“重置密码”，设置合法临时口令。
2. 甲乙分别刷新受保护页，再尝试用旧密码登录。
3. 用新临时口令登录，验证强制改密；改密完成后访问报表。
4. 另用7位临时口令重置独立账号，验证拒绝。
**功能预期**：重置成功全部旧会话失效；旧密码不可用；新登录强制改密；短口令拒绝。
**数据预期**：只有目标凭据及会话状态改变；成员/角色不变；失败重置不改变原密码和会话。

## I10 管理员授予、取消与权限边界

**目的/追溯**：链路5；系统角色仅由超管管理。
**前置与数据**：it.super、it.admin、新USER副本；该USER已登录。
**步骤**：
1. 超管将副本账号授为ADMIN；目标重新进入账号和组织管理。
2. 普通ADMIN尝试将另一USER授为ADMIN，并尝试修改超管角色。
3. 超管取消副本ADMIN角色；目标在已打开的管理页再次尝试创建账号。
4. 超管尝试修改自身角色。
**功能预期**：只有超管可授予/取消别人的ADMIN；普通管理员和修改超管自身路径被拒；降权后不能继续管理。
**数据预期**：目标仅USER↔ADMIN，不产生第二个超管；拒绝动作无角色变化；组织成员资格不因系统角色自动变化。

## I11 禁用账号的跨域影响

**目的/追溯**：链路6、32；禁用即时失权。
**前置与数据**：it.receiver副本已登录两处，为订单组成员，同时是服务规则、组织规则收件人；各规则另有有效接收人。
**步骤**：
1. 管理员在账号管理禁用目标账号。
2. 目标两个会话刷新报表，再用正确密码重新登录。
3. 查看组织成员与两类规则收件人，并尝试将被禁用者重新选为接收人。
**功能预期**：所有会话失效、不可登录、不能新选为接收人；其他人照常使用。
**数据预期**：账号状态禁用；直接成员关系保留但不授有效权限；所有相关收件关系移除；规则不因移除而自动关闭，其他接收人与通道不变。

## I12 启用账号不恢复告警收件关系

**目的/追溯**：链路6、32；恢复资格与恢复订阅分离。
**前置与数据**：I11禁用后的账号与规则副本。
**步骤**：
1. 管理员启用账号，用户重新登录。
2. 用户查看订单组大盘；配置者检查原服务/组织规则收件人。
3. 配置者明确重新选择该用户，再保存相关收件配置。
**功能预期**：可登录、原成员路径重新授予访问权；不自动重新接收通知，须显式加入。
**数据预期**：原直接成员关系未重复新增；启用动作不恢复收件记录；显式加入后才存在收件关系，窗口重建按A17验证。

## I13 慢阈值配置仅影响后续数据

**目的/追溯**：链路19；平台配置与分类时刻一致。
**前置与数据**：自身URL独立窗口，先使用1000ms阈值；两批自身记录受控耗时变体各1200ms，分别在阈值改1500ms前后处理。不要求真实平台请求精确1200ms，也不在共享环境人工拖慢请求；无受控能力则分类边界BLOCKED。
**步骤**：
1. 第一批分析完成后查看慢请求确认已归类。
2. 管理员进入平台配置将慢URL阈值改为1500ms并保存，刷新读回。
3. 产生第二批1200ms调用，再查两批各自时间范围及全范围。
4. 恢复阈值1000ms，确认历史第二批不会被重新归类。
**功能预期**：配置保存可读回，慢分类只影响之后处理；历史页面筛选不重定义类别。
**数据预期**：两次Transaction都计数；慢请求只保留第一批1次，前后历史不重算；SQL/Call/Cache阈值不被该次保存意外改0或改缺省。

## I14 通知通道配置与可选范围

**目的/追溯**：链路26、通知通道；配置完整性。
**前置与数据**：管理员，隔离通道配置/记录型适配器可用；邮件、钉钉、飞书分别准备未配置/字段完整状态，使用非真实测试凭据且禁止外发。不需要连接外部接收服务；无安全隔离配置能力则相关项BLOCKED。
**步骤**：
1. 打开平台配置查看三个通道；进入告警表单查看可选项。
2. 管理员配置一个通道的合法参数并保存，重新打开配置页和规则表单。
3. 在独立配置副本尝试只打开开关但不补必需参数，再检查可用性。
4. 对其余两个通道重复完整配置检查。
**功能预期**：未配置完整的通道不可选，字段完整按产品配置规则可选；本例只验配置校验/持久化/选项，不声称虚拟凭据能真实投递；远端凭据验证或送达另留A18可选专项。
**数据预期**：各通道配置相互独立且刷新后保留，保存一个不清空另两个；密钥不公开回显。真实送达另见A18，当前不支持的配置入口记缺口。

## I15 普通用户不可管理平台与账号

**目的/追溯**：链路2、5、7；总纲权限矩阵。
**前置与数据**：it.outsider正常登录；已存在账号、组织、平台配置。
**步骤**：
1. 以普通用户尝试进入账号管理、建组织/管理成员、修改慢阈值及通知通道。
2. 对已知管理页地址直接访问，尝试提交修改。
3. 同一用户查看服务报表及创建服务告警作为允许对照。
**功能预期**：管理动作拒绝，不以菜单隐藏作为唯一保护；服务报表与服务告警正常允许。
**数据预期**：全部拒绝动作不改变账号、组织、成员及平台参数；允许动作只修改相应服务规则，不产生组织权限。
