# NeoCat 自身打点与用例对应表

本册的唯一被监控应用是NeoCat本身。此表是测试数据来源和待补齐能力清单，不是功能实现报告；本次只改文档，没有新增打点、测试入口或修改现场数据。117条用例ID及产品预期保持不变。

## 1. 自身操作与观测目标

| 自身操作/活动 | 所需打点与安全要求 | 用例 |
|---|---|---|
| 登录、退出、改密、组织树查询、账号/成员/大盘管理 | URL Transaction记录方法+路由模板、实例、开始时间、实际耗时、结果；认证拒绝也有结果。不含查询参数、账号路径值、密码、Cookie或请求体 | K01–K03、I01–I15、G01、R01–R06、Q10 |
| 组织创建成功与同父重名拒绝 | 每次操作一个 `organization/node-create` Event，区分成功/失败，不把同一异常重复报告多次 | K03、G01、R07–R08 |
| 成员直接加入及祖先成员继承 | `neocat.org.effective_members`记录目标叶子的有效人数，标签 `org`、`membership=direct/inherited`；仅隔离测试组织使用可识别标签，生产名称/基数另评审 | K04、R16–R20、D02 |
| 平台后端实际JVM采样 | 每实例Heartbeat，保留事件时间、单位和字段presence；未定义max/Full GC不补0。采样不依赖用户登录 | K04、R14–R15 |
| 平台实际数据访问及内部调用 | SQL/Call等Transaction与请求上下文关联，使用稳定操作名，不存SQL参数、完整SQL文本或配置凭据；不存在的Cache操作不造假 | K02–K03、G01、R01、R08–R09、I13 |
| 自身异常及慢调用 | 真实失败状态、脱敏异常名/消息、实际节点耗时；业务拒绝与服务端故障分别留证。不以控制台一条WARN替代监控Event/Problem上报 | K03、R08–R09、Q10 |
| 规则评估、目标取值及通知分发 | 可关联规则标识、完整分钟、基线、输入质量、条件真值、窗口、接收人数、通道及尝试/失败；不含接收地址、密钥和完整通知体 | K07–K08、G09、A01–A20、Q08 |
| SDK发送、队列、接收、分析、落存与查询 | 可区分接受/丢弃/失败/完成及耗时，能对照树标识；发送失败仍保留不依赖本条上报成功的本地脱敏证据 | G03–G16、Q01、Q03、Q06–Q09 |

URL仅按稳定路由模板命名，例如 `GET /api/orgs`；有ID的路由使用 `{id}` 等模板，不把每个账号/节点ID变成新Name。成员Metric是业务数值，不是请求耗时或URL次数的替代。

## 2. 两类样本必须分开

### 真实自身操作（主闭环）

1. 在平台页面完成实际登录、组织查询/创建、成员变更等活动，记录实际请求和业务结果。
2. 平台内打点经真实SDK和上报入口形成观测，按服务/实例/目标/窗口与操作台账核对。
3. 再在平台内验证报表、取样、Trace、卡片和规则。真实耗时及JVM值按实测计算，不套用固定示例值。

### 自身记录受控变体（边界专项）

在授权隔离运行态内，以自身操作记录为基础准备重试、ID冲突、非法协议、指定时间/耗时、缺字段、逆序到达、高基数或局部失败变体。仍需经过对应的真实校验/分析链路；不改汇总表、不直塞页面结果、不改宿主系统时钟。受控能力须默认关闭、有明确作用域且不影响其他会话或共享环境；本册不虚构任何“生成数据”页面按钮。

这类能力未实现或未授权时，相关子项BLOCKED，不能改成要求外部演示服务，也不能删掉边界验收。DS-TX-BOUND/DS-JVM-BOUND只能证明消费和计算规则，不证明实际HTTP延迟/JVM采集准确。压力容量与传输性能必须使用真实运行与测量，不用变体数据量替代吞吐证据。

## 3. 自监控的额外判定约束

- **防递归**：SDK发送、上报入口及其分析、诊断打点发送链路必须有抑制边界。查看报表的普通请求可以被观测一次，但不能因传输/分析这条观测再次无穷生成树。Heartbeat等周期任务单列基线；Q08停止人为操作后核对无自激增长。
- **不串上下文**：并发用户、后台线程、异步上报和下一次请求各自隔离；不能把查报表的请求挂到此前改密或组织操作的树上。G15/Q04核对。
- **不自证正确**：待测报表中的Hits本身不能同时充当输入真值。保留独立操作台账及发送/受理/分析证据；性能使用独立计时。监控链路故障时本地故障记录仍可取得。
- **区分两种失败**：自身查询依赖坏了，查询本身可以正确报错；应验证“监控发送失败不改变原业务结果”，而不是要求同一MySQL已不可用时组织管理仍成功。G15只隔离监控传输，Q06分别记录平台业务与监控影响。
- **区分失败记录和被拒数据**：非法树本身不进入统计，但接收端对非法上报的诊断可以留下独立安全摘要；不能为凑“零增量”关闭应有故障观察。
- **保护数据**：打点、台账、Trace及附件均不得包含密码、会话、令牌、通道密钥、完整配置或未经脱敏的异常参数。显示/隐藏密码仍仅改变当前输入框，不产生敏感观测。

## 4. 跨服务与外部通知的边界

- 正常部署是一个 `neocat-backend` 服务。Java模块、SQL存储与同服务的两个实例，都不能虚称跨服务Trace已经通过。
- K05、G10–G11、R21–R22在需要时，仅用同一后端构件的隔离角色运行态 `neocat-self-upstream/downstream/leaf`，发起实际只读调用并传播Trace上下文；不另写网关/订单/支付应用。若缺少这项受控自调用能力，跨服务子项BLOCKED；仅构造关联树可验证拼接，但不能代替真实跨运行态传播的证据。
- K07/K08及A类主流程以真实规则评估、分发意图和失败隔离为验收范围，不依赖外部收件系统。记录型适配器不等于实际送达，不新增一期之外的站内告警/投递历史页面。
- A18保留邮件/钉钉/飞书真实送达产品契约，单列为可选外部专项。未实施时明确未验收；不把 `UnsupportedExternalNotifier` 的异常计成成功。

## 5. 当前前置缺口与执行记录

已确认有独立Java SDK源码，但后端主源码未检出 `com.neocat.client` 接入引用。仅有SDK或已补全局异常控制台日志，不能说明自身URL/Event/Metric/Heartbeat及真实传输已接通。上述业务打点、上下文关联、评估/分发诊断和受控能力均须在执行前核实，缺失项登记打点/接入缺口；本次不据文本检查宣称这些能力存在或不存在于所有部署。

执行仍使用README的统一状态格式，补记样本来源（真实/受控）、自身打点版本、实例、窗口、操作台账和排除的旁路流量。未执行保持NOT_RUN；前置失败后续BLOCKED。外部送达未测不影响单独判定自身数据链路，但完整通知链路不得判PASS。
