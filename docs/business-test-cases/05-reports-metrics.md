# 第二层：报表、时间与指标（P1）

依据产品03、04及总纲统一数据口径。使用 [自身操作数据](00-test-data.md)，不部署外部业务服务；默认服务neocat-backend。真实观测按台账计算；固定耗时、指定时间/字段、类型隔离及高基数使用独立受控扩展，缺能力记BLOCKED，不冒充真实采集。只读分支优先，历史窗口单独积累。全部待执行。

## R01 Transaction Type → Name 交互

**目的/追溯**：链路17；分类层级与默认目标。
**前置与数据**：DS-TX；平台查询组织树产生实际SQL类型，查看当前账号产生另一URL Name=`GET /api/me`，各目标按台账区分，SQL仅记录稳定操作名及脱敏信息。
**步骤**：
1. 选择neocat-backend进入Transaction，查看Type汇总。
2. 点击URL，再点击GET /api/orgs。
3. 返回Type列表，再选择SQL；重复进入另一Name。
**功能预期**：Type只进Name列表，Name才进趋势；默认全部机器、Hits、当前自然小时；切换后不携带上一Name的内容。
**数据预期**：各级统计范围正确；URL下只列其Names；GET /api/orgs为100次，SQL子节点及GET /api/me不混入该Name。Type总计按实际所有适用节点核对，不把100次URL当整棵树节点总数。

## R02 多机器汇总与加权统计

**目的/追溯**：链路17、公共聚合；禁止平均均值/比率。
**前置与数据**：先使用DS-TX真实操作与实际耗时台账，仅选W；另用独立DS-TX-BOUND窗口验证固定耗时算术，两组不混算。
**步骤**：
1. 在GET /api/orgs查看全部机器汇总，记Hits、失败率、Min/Max、Avg及分位。
2. 分别选择neocat-a、neocat-b，再回全部机器。
3. 将同一批数据按分钟与更粗桶查看，对照聚合结果。
**功能预期**：切换机器与桶粒度时目标一致，展示项无丢失。
**数据预期**：真实样本全量100/10/10%，A80/4/5%、B20/6/30%；耗时按真实台账合并。受控BOUND另应Min100ms、Max500ms、Avg180ms，不能为300ms。两组分位都从合并分布重算，不平均机器/子桶分位；全量失败率不是17.5%。无BOUND能力仅阻塞固定耗时子项，不将真实延迟判错。

## R03 QPS 与 Hits 切换

**目的/追溯**：链路17、18；次数与速率分离。
**前置与数据**：完整600秒W内DS-TX100次；桶设置为覆盖整个W的10分钟点。
**步骤**：
1. 打开目标趋势确认默认Hits，查看该10分钟点及Tooltip。
2. 切换统计项QPS，再切回Hits。
3. 对DS-EVENT按同样范围重复切换。
**功能预期**：标题、图例、Tooltip随统计项一致变化；不把count/min直接标QPS。
**数据预期**：Transaction Hits100、QPS100/600；Event Hits40、QPS40/600；切换不改变底层记录或把次数除以错误的点数。

## R04 当前小时与完整历史小时 QPS

**目的/追溯**：公共QPS；实际覆盖秒数。
**前置与数据**：在专用窗口通过平台组织查询产生120次GET /api/orgs，整点后10分钟观察，无额外同目标请求；另一完整历史小时曾有360次自身调用。记录真实观察时刻，无法精确10分钟时按实际秒数，不把历史数据临时补到过期窗口。
**步骤**：
1. 在当前小时查看目标QPS，记录平台实际覆盖秒数。
2. 在稍后没有新调用时再次查看，观察分母变化。
3. 切完整历史小时查看360次目标的QPS。
**功能预期**：当前范围明确标实时/未完成，不默认视作完整一小时。
**数据预期**：整点后600秒时120/600=0.2；稍后为120/实际已覆盖秒数；完整历史小时360/3600=0.1。多机器先合次数再除公共秒数，不平均机器QPS。

## R05 机器 Top N、other 与手动选择

**目的/追溯**：链路17、18；机器对比与总量对账。
**前置与数据**：确认Top N为N；同一NeoCat构件N+2个实际隔离实例，各自查询同一自身URL，Hits N+2至1，无并列。若仅为图表/聚合边界，可用自身记录的合成实例变体验证并标来源；不能凭合成身份声称真实N+2实例接入/容量通过。
**步骤**：
1. 在Hits趋势进入机器视图，查看默认Top N与other。
2. 搜索最小实例，在分页明细中勾选它与最大实例进行对比。
3. 取消手动选择回自动视图，并测试明细排序、翻页。
**功能预期**：默认贡献降序；数量/速率类显示其余合计；手选后只画选中实例，不自动加入other；全部机器能在明细找到。
**数据预期**：Top N+other之和等于全量；手选仅两实例各自值；other不是额外一次采集。耗时/分位不能将实例值简单相加冒充other合并分布。

## R06 最近 30 条取样与筛选一致性

**目的/追溯**：链路17–19；取样真实定位。
**前置与数据**：DS-SAMPLE35条；额外在另实例、另Name及范围外各一条可识别记录。
**步骤**：
1. 查看目标行取样列表，对照事件时间顺序。
2. 将时间范围缩到部分记录，再选择单实例，随后换另一Name。
3. 打开最新与最旧的可见取样，核对Trace身份。
**功能预期**：多行倒序最多30条，过滤条件一致；最老失败调用不插队；每条打开对应Trace。
**数据预期**：初始为35条中最新30条，排除最旧5条；其他实例/Name/范围外记录不能混入；排序以事件发生时间而非接收顺序。

**步骤**：

## R08 Problem 五类、重叠与名称聚合

**目的/追溯**：链路19；分类规则。
**前置与数据**：DS-PROBLEM；完整异常消息两种、异常名相同。
**步骤**：
1. 依次打开异常、慢请求、慢SQL、慢调用、慢缓存。
2. 在异常查看同名项并打开其取样，再进入失败且慢的URL所在两类。
3. 检查各类统计项，选择合法环比范围。
**功能预期**：异常按异常名，不以完整消息拆成两行；慢类按Transaction Name；异常无耗时分位，慢类有。
**数据预期**：同名两异常聚合2次、消息在样本分别保留；失败慢URL同时计入异常和慢请求，每类一次，不能将类别总和冒充去重调用总数。

## R09 慢阈值等值边界与历史筛选

**目的/追溯**：链路19；“超过”与筛选不重分类。
**前置与数据**：DS-PROBLEM的自身记录受控耗时变体，每类阈值下1/等值/上1ms；独立SQL节点150/200/250ms各1条、阈值100ms。不是要求真实MySQL恰好执行这些耗时，普通页面等待不能代替SQL耗时；受控能力缺失则精确边界BLOCKED。
**步骤**：
1. 在四个慢类分别查看边界样本是否归类。
2. 在慢SQL将页面自定义筛选设为高于199ms，再高于249ms。
3. 清空自定义筛选，再将页面筛选降低到50ms。
**功能预期**：页面筛选只作用于已归类慢记录，支持精确历史过滤；不是重算平台慢阈值。
**数据预期**：四类仅阈值上1ms进入；SQL专用组高于199ms为2次、高于249ms为1次、清空为3次；降低页面筛选不能把未归慢类的低耗时记录加入。

## R12 零值、缺数与未来时间

**目的/追溯**：统一数据质量；不以0伪装断流。
**前置与数据**：同一自身目标有操作点、完整性可证且未查询的零点、只对此目标可控制造的分析失败点、未来点四组。停整个平台无法区分根因；没有完整性证据/局部故障能力则对应子项BLOCKED，不凭无上报认定零。
**步骤**：
1. 分别查看Hits、失败量、QPS、失败率、Avg及分位趋势。
2. 打开四组点Tooltip，再进入使用该序列的卡片和预告警。
3. 尝试将时间窗口前进到未来。
**功能预期**：有数据正常显示；零值与缺数可区分；未来不伪造观测，时间控件不允许无意义前进。
**数据预期**：确认零调用的Hits/Failures/QPS为0，耗时/失败率/分位无值；失败/未出现/未来点为null及相应原因；图表断线、卡片缺口、预告警数据不足保持同一语义。

## R13 日/周/月环比与分位重算

**目的/追溯**：链路17–19、21、23；比较口径。
**前置与数据**：当前范围及平台日期偏移1、7、30天的同时段样本；额外有上一个自然月但不在30天偏移日的数据；各桶分布已知且不均匀。
**步骤**：
1. 在Transaction选择1天、7天、30天环比，对照桶时间。
2. 对Event、Problem、Metric重复；检查Heartbeat不出现环比。
3. 在有多个子桶的范围查看Avg及分位，比较合并后的原始分布。
**功能预期**：按同时段桶序号对齐，30天不是上自然月；缺历史不伪造值。
**数据预期**：对比命中正确偏移日，按平台时区整日偏移；Avg按总耗时/总数，分位从合并分布重算，不能平均子桶结果；Event和异常Problem仍不提供不适用耗时项。

## R14 Heartbeat 实例隔离与 Top N

**目的/追溯**：链路20；JVM指标不是可相加的业务次数。
**前置与数据**：DS-JVM真实采样，必要时同构件额外N+1个实际JVM实例验证Top N；图表算术另用DS-JVM-BOUND/合成实例变体并注明。非JVM对照不另建应用，使用独立自身测试身份只上报合法URL/Event而不报Heartbeat；它仅证明无Heartbeat时的入口行为，不证明存在真实非JVM采集器。
**步骤**：
1. 查看堆使用与线程图，对照neocat-a/neocat-b的真实独立采样曲线。
2. 查看Top N，再在搜索/分页实例表加入其他实例。
3. 切到仅有URL/Event、无Heartbeat的自身测试身份，检查入口；不把运行中的Java后端称为非JVM应用。
**功能预期**：按实例及当前指标排序，无other合并JVM曲线；无Heartbeat数据不显示假采样，无环比；真实非JVM应用兼容性不在本次自身验收证据内。
**数据预期**：实际桶值与各实例台账最后采样一致，不求和/平均。BOUND组另应350/550MiB、线程12/22，不能合成900MiB/34线程作为一个JVM；手选曲线数正确。缺额外实际实例时真实多实例规模子项BLOCKED。

## R15 Heartbeat 缺字段、累计值与指标说明

**目的/追溯**：链路20；观测时序与presence语义。
**前置与数据**：DS-JVM实际采样核对来源，DS-JVM-BOUND在自身发送路径控制先新后旧；元空间max未定义、Full GC缺失/有可靠来源、明确0值各受控一组。只有变体没有真实来源时不能声称采集器已正确提供Full GC。
**步骤**：
1. 查看堆、内存分区used/committed/max、GC与线程指标。
2. 将同桶两次观测逆序到达，刷新；再重复同一次观测。
3. 悬停/键盘聚焦/触屏打开指标旁“?”，查看单位与语义，再收起。
**功能预期**：按事件时间最后采样；说明不撑高图表，可收起；未定义指标不伪装为0。
**数据预期**：累计GC为最后7/9，不求和、不擅自换成增量；committed不当used，元空间不算进堆；缺字段null、真实0保留0；旧观测及重试不覆盖最新值；没有可靠Full GC来源时不猜测。

## R17 Metric 标签规范化、OR/AND 与清空
