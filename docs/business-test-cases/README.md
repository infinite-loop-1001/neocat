## 2. 阅读入口与执行批次

分册入口：[核心闭环](01-core-journeys.md) · [平台身份](02-platform-identity.md) · [组织权限](03-organization.md) · [上报与Trace](04-ingest-trace.md) · [报表指标](05-reports-metrics.md) · [大盘卡片](06-dashboards.md) · [告警通知](07-alerts.md) · [跨域专项](08-cross-cutting.md)。

1. 先读 [共用测试数据与判定约定](00-test-data.md)，准备角色、组织、服务和确定性样本。
2. 先执行 [核心闭环 K01–K08](01-core-journeys.md)。已初始化环境只跳过 K01 的首次初始化子项，不跳过后续账号和组织准备。
3. 再按树中的分册执行功能分支；负例使用独立对象，不污染核心样本。
4. 最后执行 [跨域专项 Q01–Q12](08-cross-cutting.md)。删除、禁用、故障、压力和留存测试放在最后并隔离开展。

**共 117 条用例**：核心 8 条、平台身份 15 条、组织 12 条、上报 Trace 16 条、报表指标 22 条、大盘 12 条、告警 20 条、跨域专项 12 条。P0/P1/P2 表示执行先后，不表示低优先级的权限或安全缺陷可以忽略。

## 3. 用例写法与验收边界

- 每条包含：目的、前置与数据、编号业务步骤、功能预期、数据预期、追溯。分册默认优先级见标题，例外单独注明。
- “点击某操作”指相应业务入口；不是断言当前版本已经有该按钮。**页面缺入口时登记功能缺口，相关 UI 子项 BLOCKED；不能自行改成接口调用后声称 UI 通过。** 无页面的上报、停机、故障场景，步骤写为业务活动，不虚构平台按钮。
- 数据预期描述应保存的对象、数量、范围、状态与计算值；核查方式由执行者选择，本册不规定 SQL 或工具。单看成功提示不能证明数据正确。
- 接收数据不等于完成分析，保存规则不等于启用，命中规则不等于通知送达。分开记录各子项。
- 所有预期以产品行为为准；现有缺陷不能写成“预期失败即通过”。技术错误码、部署与执行方法见 [现场操作手册](../development/integration-test-runbook.md)，其过时字段不覆盖产品事实源。

## 4. 当前执行限制（不是通过证据）

- 前端已补充 `/initialize` 开通页及初始化状态错误/重试页：未初始化时自动引导，已初始化时回到登录。相关离线路由/表单测试不代表 K01/I01 真实开通已通过，现场子项仍待执行。
- 部分页面仍为简化交互，例如完整成员选择、卡片编辑排序、多条件与收件人选择；执行时逐项确认，不以默认示例账号或固定目标冒充用户选择。
- 真实外部通知适配器 `UnsupportedExternalNotifier` 尚不支持发送。K07/K08 的真实送达子项及 A18 成功路径当前受阻；可独立验证失败隔离，但不能据此判“已送达”。
- 现有操作手册记录了 SDK 独立上报鉴权、卡片阈值线和规则持久化等风险；这些是待复核项，不是本册已执行缺陷清单。
- 本次仅编写文档，不执行初始化、发通知、停服务、改配置或业务数据；不宣称真实中间件或生产容量已经验证。

## 6. 结果记录与判定

记录格式：`用例 ID｜版本/日期｜测试数据批次｜实际功能结果｜实际数据结果｜PASS/FAIL/BLOCKED/NOT_RUN｜证据｜缺陷或阻塞原因`。

- **PASS**：所有步骤的功能、数据、无副作用要求均有证据；多组数据逐组记录，不能用一组替代全部。
- **FAIL**：实际业务行为或数据违反预期。已知缺陷仍记 FAIL，不改写预期迁就实现。
- **BLOCKED**：缺少环境、合法数据、入口或可控故障条件；写清未验证的子项。入口本身缺失同时登记产品缺口。
- **NOT_RUN**：尚未执行。不存在“部分通过后整条默认通过”；拆记子项并保留整体未完成状态。

通知、压力、删除、禁用只在授权隔离环境进行。用例相互依赖时，前置失败的后续项记 BLOCKED；不靠手工改业务记录制造“成功”。证据需脱敏，不保留密码、会话、令牌或通道密钥。
