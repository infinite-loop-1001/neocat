# MySQL 分布式锁规范

## 强制约束

- 使用 InnoDB `SELECT … FOR UPDATE`，完整主键 / 唯一索引键等值命中；禁止范围条件、非唯一普通索引、`GET_LOCK`、进程 synchronized 冒充分布式锁。
- 已有业务行可直接锁业务行；无业务行的临界区使用独立锁表。不存在的行不能作为已获得互斥锁的证据。
- 独立锁表先以主键幂等建立锁行，再 SELECT FOR UPDATE；不使用 INSERT IGNORE 吞掉其他错误。
- 加锁、读取共享状态、业务操作位于同一事务 / 连接；提交与回滚自动释放锁，不提前提交，不异步逃逸持锁事务。
- 事务必须有有限超时；锁超时 / 死锁失败必须传播，禁止捕获后继续无锁执行。
- 多锁遵守固定顺序。禁止将数据库锁表变成无界高基数缓存；优先稳定的业务范围锁键。

## 语义边界

- 互斥不等于去重：一次性初始化需持锁后重新校验初始化状态；定时任务「一次执行」还需共享执行进度。
- 不可将各实例的内存分钟桶刷盘、小时释放变成全局仅一个实例执行。
- 告警窗口目前位于内存，仅加互斥锁不能实现跨实例窗口连续性或投递去重。
- MySQL 锁不能保证 MySQL / ClickHouse / 外部投递跨系统原子性。
- 不引入外键；新增锁表同时提供新库 DDL 与已有库增量迁移。

## 验证

离线使用 Spock Mock / Stub 验证 SQL、事务顺序、回滚、失败不执行临界区，不连接中间件。现场使用真实 MySQL 两个独立连接验证同键阻塞、异键并行、提交 / 回滚释放、等待超时及 EXPLAIN 索引。现场未执行时标记 NOT_RUN，不以 Mock 成功替代真实互斥验证。
